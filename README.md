# ПП.ПМ.12 «Программирование мобильных игр»

Третий этап сквозного проекта: завершённая игра на основе механики УП.ПМ.12 и оформления УП.ПМ.13. Продолжительность — 3 недели; точные сроки задаются в ЛМС.

Учебный ресурс: https://olgakraven.github.io/2026-pp.pm.12-rvmp/

## Комплект

- Задание и 30 отдельных вариантов с сохранением номеров и тематик предыдущих практик.
- Подробная инструкция: теория, пронумерованные действия, реальные снимки Unity, проверки и типичные ошибки.
- Полный код из единственного источника `unity-project/Assets/Scripts`.
- Контрольный проект «Кристальный маршрут»: три уровня, прогрессия, меню, пауза, громкость, рекорды и сохранения.
- Два PDF A4 в альбомной ориентации и три раздела сайта: «Задание», «Инструкция и образец», «Предметные области».

Студентам выдаётся `assignment.pdf` через ЛМС. Инструкция и образец выдаются по решению преподавателя. Для сдачи обязательна ссылка на доступный преподавателю репозиторий с Unity-проектом и хеш итогового коммита.

## Запуск

1. Откройте `unity-project` в Unity 6.6 (6000.6.2f1).
2. Откройте `Assets/Scenes/Main.unity` и нажмите Play.
3. Выберите уровень 1. Управляйте WASD, стрелками или экранными кнопками.
4. Соберите все кристаллы и войдите в зелёный портал.
5. Проверьте открытие следующего уровня, паузу, настройки и повторный запуск.

Параметры уровней изменяются в `GameRoot → Level Manager → Levels` вне Play. Поле и Canvas создаются кодом во время запуска. `SaveService` хранит открытые уровни, рекорд каждого уровня и громкость; незавершённая попытка не восстанавливается.

## Сборка материалов

```sh
python -m pip install -r requirements.txt
python scripts/build.py --release
python scripts/check.py
python -m http.server 8000 --directory site
```

Результат в `site/downloads`: `assignment.pdf`, `guide.pdf`, `PP12-CrystalRoute-UnityProject.zip`, полные файлы C#. GitHub Actions собирает тот же комплект и публикует GitHub Pages.

## Проверка и границы

Фактические проверки и ограничения записаны в `docs/VERIFICATION.md`. Для повторяемой проверки в копии проекта используйте `Practice → Verify And Capture`. Эта проверка вызывает методы игры; сама по себе она не доказывает физическое управление мышью или сенсорным экраном.

Android-сборка не является обязательной: она требует установленного модуля Android Build Support. Проверка редактора не заменяет проверку на устройстве.
